- Delivery namespace (post-C1, commit `d815f8b`): `/capsules` family only.

## 3. Finalised requirements (accepted in principle)

1. **Function-by-function mapping** — finalised from the duplication inventory:

   | Existing function | Current file | Proposed shared function | Behaviour identical? | Page-specific logic remains? |
   |---|---|---|---|---|
   | `b64encodeBytes`/`b64decodeBytes`/`b64encodeStr`/`b64decodeStr`/`b64urlEncode`/`b64urlDecode` | index + receive | shared b64 module | yes (encode/decode semantics identical; receive lacks encode-str) | no — all pure |
   | `wasmBlake3Hex`/`wasmBlake3BytesHex` + wasm calls | index (+ inlined in receive) | shared wasm helper | yes | no — engine-level |
   | `makeTextEnvelope`/`makeImageEnvelope` | index | shared envelope-builder | yes (creation) | orchestration (studio UI) page-specific |
   | `finalizeEnvelope`/`resolveNotes` | receive | shared envelope-resolver | yes (reception) | orchestration (inbox) page-specific |
   | `postCapsule` delivery | index | shared delivery helper | yes | no |

2. **Base64 compatibility** — verified from source:
   - Text: `b64encodeStr` = `btoa(unescape(encodeURIComponent(s)))`; `b64decodeStr` = `decodeURIComponent(escape(atob(b)))` — identical in index (`b64encodeStr`/`b64decodeStr`) and receive (`b64d`). ✅
   - Binary: `b64encodeBytes` = binary-string→`btoa`; `b64decodeBytes` = `atob`→`Uint8Array`. ✅
   - URL-safe: index `b64urlEncode`/`b64urlDecode` ≡ receive `b64urlDecode` (+ index encode). ✅
   - Invalid/malformed: `atob` throws on bad input; callers guard (`try/catch`, 'Still preparing', blake3 'pending'/'mismatch'). Shared module must preserve throw/return contracts.

3. **WASM lifecycle** — documented:
   - Ownership: module-scope `init()` per page; `window.WasmSpim`, `window.blake3_hex_static`, `window.wasmReady=false`, `window.wasmInitPromise=init().then(...)`.
   - Loading order: init before engine use; guards `if(!window.wasmReady) await window.wasmInitPromise;` before `new WasmSpim` / `from_encoded_bytes_b64`; `wasmBlake3Hex` → `'pending'` when not ready.
   - Failure: errors surfaced via page UI (`showErr`, `showImageError`, postcard error titles).
   - Duplicate-init prevention: one module init per document; window globals per document.

4. **Browser compatibility** — preserved:
   - index inline `onclick="createText()"` → shared functions must attach to `window` (or handlers moved) to stay reachable; receive uses addEventListener + window functions.
   - Required window globals: `window.WasmSpim`, `window.blake3_hex_static`, `window.wasmReady`, `window.wasmInitPromise`.
   - Existing script loading: keep `/js/` module pattern and deferred semantics.

5. **Regression tests** — plan: text creation/reception, image creation/reception, CAP1 envelope, binary reconstruction, consume/single-view, error handling — via existing local harnesses (`seam-capsule-test`, `seam-image-browser`, `parity`/`makewav` where applicable, local site flows) plus deployed-route checks.

6. **Page-specific logic stays outside shared module:** studio UI, inbox rendering, search, audio/beam/catch, quota/dock — remain page-local; shared module holds only primitives/builders/resolvers/delivery.

## 4. Risks & rollback (summary)
- Shared module must preserve window-global reachability for index inline handlers; CSP allows `/js/` modules (`script-src 'self'`).
- Rollback: revert commit; no engine/WASM semantics change.

## 5. Acceptance criteria (C3)
- Behaviour identical pre/post extraction; regression suites green; no out-of-scope changes.
